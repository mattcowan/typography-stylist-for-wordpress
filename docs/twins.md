# Twins: logic that exists in more than one place

A twin is logic or data that exists in two or more places and must be kept in step by hand: PHP and JavaScript (the paragraph style CSS generators, sanitizers and normalizers, constant lists), JavaScript and JavaScript (the block's webpack build, the inline editor's browserify build, and the hand-written ES5 scripts that have no build), and CSS and JavaScript (a selector or a condition in a stylesheet that a JS function mirrors). This file lists every twin found for #358 and the test that fails when one copy changes. Each test named here was checked by changing each copy once and seeing the test fail (see "How a row was checked" at the end), except where the row says it was not.

When you change one copy, change every copy in its row in the same commit, and run the named tests. When a row says the copies differ, the difference is pinned by a named case in its test: changing it is a decision, not a fix.

Paths are from the plugin root. "ps-utils.js" is `paragraph-styles/assets/js/lib/ps-utils.js`, "the module PHP" is `paragraph-styles/paragraph-styles.php` (class `Typost_Paragraph_Styles`), "utils.js" is `blocks/typography-stylist/utils.js`.

## How to add a twin

1. Prefer no twin. Code shared by the block's build and the inline editor's build goes in one CommonJS module in `assets/js/` that both builds load (as `text-case.js`, `font-size-units.js` and `font-weights.js` do), and `utils.js` re-exports it. Never `require` `utils.js` from the browserify build: it bundles the whole file and sets `window.typostSharedUtils` a second time. A hand-written ES5 script (the module scripts, `assets/js/admin-*.js`, `assets/js/editor-font-kits.js`) cannot import at run time, so it keeps a copy.
2. A PHP/JS twin gets a shared JSON fixture that both suites read: inputs and the exact expected output. Module pairs put it in `paragraph-styles/__tests__/fixtures/`; core pairs in `tests/fixtures/`. The Jest reader is a `*.test.js` beside the module's tests, and the PHPUnit reader is a `tests/Unit/*Test.php` that loads the fixture through `TYPOST_PLUGIN_DIR` and calls the PHP method (through reflection when it is private; do not make it public for the test). Both readers also assert that the fixture is read (an empty data provider passes by never running). Generate the expected strings from the current code, then check the other side against them; never edit source to make a fixture pass.
3. A JS/JS twin gets a Jest test that runs every copy on the same inputs and compares the results. A copy that cannot be imported (an ES5 script with no export, a function that is not exported, a class method, an object literal assigned at load time) is cut out of its source and run with `tests/js/twin-source.js` (`loadFunction()`, `extractFunction()`, `extractBlock()`); it throws a message that names the file and the symbol when the code was renamed or moved. That helper sits outside the folders Jest collects, so it is not a test. Compare behavior, not source text.
4. A CSS/JS mirror gets a Jest test that reads the stylesheet rule and checks the JS against it (see `blocks/typography-stylist/__tests__/css-js-mirrors.test.js`), with a control case that proves the rule was found.
5. Where the copies must differ, write the difference as a named case (a label that starts with `differs:`) that pins each copy's current output.
6. Change each copy once, run the test, see it fail, undo. Add the row below.

None of the fixtures or tests ship: `.distignore` excludes `__tests__`, `/tests` and `/docs`.

## How a row was checked

For each copy in a row, one change was made to the copy (a constant, an operator, a rounding step, a list entry, a string), the tests the row names were run, and the file was restored byte for byte before the next change. A row counts as checked only when a named test failed for a change to each of its copies. [twins-mutations.md](twins-mutations.md) lists the change used for each copy and a test that failed.

- Code: the 2.4.0 refactor at commit 936ebff (wave 1 merged), with these tests.
- Jest as `npm test` runs it. PHPUnit 9.6 on PHP 8.4.0; the PHP test files also pass `php -l` on PHP 7.4. PHP 7.4 and 8 disagree on some inputs (`is_numeric()` accepts trailing whitespace only from PHP 8), so the shared fixtures leave those inputs out, and a difference that only PHP 7.4 shows is not covered here.
- Some changes alter no output for any input and were not counted as gaps: the `1e-7` epsilon in the zoom slope (`responsive_zoom_vw()`, `responsiveZoomVw()`, `getResponsiveZoomLimit()`), and the `trim()` before `is_numeric()` in `normalize_hang()` on PHP 8.
- Rows 24 and 25 (code that #364 was changing at the time) and the NO TEST rows were not checked this way; each says so.
