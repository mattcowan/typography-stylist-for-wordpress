# Admin settings page

- **Topic:** the Settings → Typography Stylist page: its tabs, the no-reload refresh after a font action, the language and entity rules for its REST calls and localized strings, and why fonts load only for the open tab.
- **Issues:** #226, #296, #307
- **Code:** `includes/admin-page.php`, `assets/js/admin-page.js`, `includes/class-typost-assets.php`, `includes/class-typost-rest-controller.php`

Moved from the root [CLAUDE.md](../../CLAUDE.md) by #361. The screen reader rule for the settings tabs (#349) is in [screen-reader-rules.md](screen-reader-rules.md); Export & Import is in [export-import.md](export-import.md).

**Admin Interface:** [includes/admin-page.php](../../includes/admin-page.php)
- Tabbed interface showing: Presets, Font Features, Custom Fonts, Accessibility, Options, Help
- Font management: Upload webfont kits, Adobe Fonts integration, custom font definitions
- Font preview for testing OpenType features
- Options tab: Clear confirmation settings, archive page font detection, manual cache clear button
- Inline styles and jQuery for tab switching
- Located at Settings → Typography Stylist
- **No-reload AJAX architecture (v2.3+):** every font action refreshes the page in place instead of reloading. `GET /typost/v1/admin/refresh` returns server-rendered fragments from the shared template functions `typost_render_font_list_section()` / `typost_render_preview_font_options()` (so PHP extension hooks render identically in fragments), plus refreshed `typostAdmin` data arrays and font CSS (`--font-N` variables, admin @font-face, Adobe stylesheet URLs). JS swaps `#typost-fonts-region`, repopulates the preview select (selection preserved), re-inits sortable, and re-attaches dismiss buttons on `.is-dismissible` notices (WP core only wires those at page load). The Options/Accessibility/Clear Cache forms POST to `admin/options`, `admin/accessibility`, `admin/clear-cache` (all `manage_options`), keeping their PHP POST handlers as the no-JS fallback; the color scheme restyles live by swapping `#typost-admin-color-scheme-inline-css`. Updates are announced through the polite `#typost-live-region`; the `typost:font-saved` / `typost:fonts-added` `waitUntil` contract still gates the refresh (see HOOKS.md). On refresh failure the page falls back to `location.reload()` so it can never sit stale. **Language (#296):** every REST call in `admin-page.js` wraps its URL in `typostWithUserLocale()` (`_locale=user`) and sets `dataType: 'json'`, so the refreshed fragments and server error messages use the admin's profile language, not the site's. Both are needed: `determine_locale()` reads `_locale=user` only when `wp_is_json_request()` (a JSON `Accept` or `Content-Type`), and a bare jQuery GET sends `Accept: */*`. A source-scan test in `admin-page.test.js` fails on a call that skips either. The Paragraph Styles and Variable Fonts admin scripts on the same page do the same for every REST call through their own `withUserLocale()` twins (the #292 admin-card requests had the parameter but not the header, so they still came back in the site language); a parity test in `admin-page.test.js` holds the three copies together, and each module has its own source-scan test. **Entities (#307):** `typostAdmin.strings` is a nested array, and `WP_Scripts::localize()` decodes entities only in top-level values, so its `esc_html__()` values arrive encoded (`d&#039;accessibilité`), and the REST routes' `WP_Error` messages are `esc_html__()` too. The `.html()` concatenations need that form; every `.text()`, `textContent`, `alert()` and `confirm()` that shows a localized string or a server message goes through `typostDecodeEntities()` first (also inside `announce()`, `settingsFormMessage()` and `typostBeginBusy()`). `typostEndBusy()` does **not** decode: most callers restore a label read back with `.text()`, which is already decoded, and decoding it again would turn a literal `&lt;` in a label into `<`; callers that pass a localized string decode it themselves. Source-scan tests in `admin-page.test.js` fail on an `alert()`/`confirm()` that skips the decoder, on any `.text(…)` or `textContent =` sink (whole source, so calls split across lines count) whose value is neither decoded nor on the test's allow-list of non-localized values (DOM text, numbers, file names, `__()` category titles), and on a `typostEndBusy()` label that is neither decoded nor read from the DOM; a control test plants unsafe sinks and proves the scan finds them. A new sink with a non-localized value goes on the allow-list. After the swap core triggers `typost:font-list-refreshed` (v2.3.1): page-load setup done on font cards (Variable Fonts' `setUpSettingsContainers()`: weight checkboxes for "hide weights" fonts, and Detect axes on remote fonts when `canDetect()` is false) must re-run there, or it silently reverts after every font action.
- **Fonts load only for the open tab; card headings and Adobe kits only when on screen (v2.3.1, #226):** a browser downloads the font of every *rendered* element, on screen or not (`content-visibility: auto` does not help — Chromium requests the font at style computation, measured), and the Custom Fonts tab is the default tab. So `enqueue_admin_assets()` no longer calls `enqueue_adobe_fonts()` (the editor still does — out of scope), card headings past the first `TYPOST_ADMIN_EAGER_FONT_CARDS` (12) carry `data-typost-font-family` instead of an inline style (`typost_font_heading_attributes()`), and every element that needs an Adobe kit carries `data-typost-font-id`. `window.typostAdminFonts` (`typostCreateAdminFontLoader()` in `admin-page.js`) is an IntersectionObserver that applies the family and adds the kit `<link>` once the element is in view; hidden tabs report "not intersecting", so they cost nothing until opened. It rescans after the refresh swap (the refresh payload no longer carries `adobeCssUrls`). The Feature Visibility fieldsets (51 checkboxes, ~24 KB per font) are built by `typostBuildFeatureVisibilityFieldsets()` from `typostAdmin.features` / `.featureCategoryTitles` / `.fontFeatureVisibility` on the section's first `toggle` (a capture listener — `toggle` does not bubble). Assets hook `admin_enqueue_scripts` once via `maybe_enqueue_admin_assets()`; the old `admin_print_styles-`/`admin_print_scripts-` pair printed every localized object twice. On a 148-font test site: page HTML 5.97 MB → 1.84 MB, 133 → 12 font downloads on the default tab, 154 → 0 Typekit requests on `&tab=options`.
