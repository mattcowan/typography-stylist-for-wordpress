# Case

- **Topic:** the Case setting (`textCase`, `fakeSmallCaps`) on the block, on inline spans and in paragraph styles, and the rule that every `data-*` attribute the inline editor writes must be registered on the format type.
- **Issues:** #214, #277, #309
- **Code:** `assets/js/text-case.js`, `blocks/typography-stylist/components/inspector/case-panel.js`, `assets/js/block-editor.js`, `assets/js/inline-editor/`, `blocks/typography-stylist/utils.js`, `paragraph-styles/paragraph-styles.php`, `paragraph-styles/assets/js/lib/ps-utils.js`

Moved from the root [CLAUDE.md](../../CLAUDE.md) by #361.

**Case (v2.3.3+, #214):**
- Block attributes `textCase` (string, default `''`) and `fakeSmallCaps` (boolean, default `true`). Values: `''` Default (theme case, writes nothing — byte-identical save for existing blocks and styles), `'none'` Normal (explicit reset), `'uppercase'` / `'lowercase'` / `'capitalize'` (All Caps / Lowercase / Title Case), `'small-caps'` / `'all-small-caps'`. Inspector "Case" panel; the fake small caps toggle shows only for the two small caps values, and an All Caps note covers readability and screen readers.
- **One mapping, three copies:** `caseDeclarations()` in `assets/js/text-case.js` (CommonJS, required by `block-editor.js` through browserify and imported/re-exported by the block's `utils.js`, like `font-size-units.js`), its twin in ps-utils.js, and PHP `Typost_Paragraph_Styles::case_declarations()` (keep identical; the pair order is part of the byte-identical style CSS; a Jest parity test holds the JS twins together). Case is one exclusive choice, so every value sets both mechanisms: a transform also writes `font-variant-caps: normal`, small caps also write `text-transform: none` (a theme that uppercases h2 would otherwise turn Small Caps into full capitals — `smcp` leaves capitals alone) plus `font-synthesis-small-caps: auto|none`. `font-variant-caps` rather than `font-feature-settings` because only it synthesizes; the block's `smcp`/`c2sc` toggles stay on `font-feature-settings`, which applies after `font-variant-caps`, so they keep working.
- Style-owned: captured, diffed when the state reports `textCase` (both core editors do), normalized on apply to `''`/`true`, carried by `buildPropertiesForStyleSave()` when an editor does not report it. Stored as `textCase` (never `''`) and `fakeSmallCaps: false` only when off with a small caps value.
- **Inline spans:** the inline editor has a Case select (+ the fake small caps toggle) and writes `data-textcase` / `data-fakesmallcaps` (`"false"` only, small caps only — `buildInlineCaseAttributes()`) plus the `caseDeclarations()` CSS, skipped under an active paragraph style like every span declaration (the help text then says to Detach first, as for the size). `readInlineCase()` reads it back; `_recordChange('textCase')` + `buildInlineCasePatch()` set or remove all three declarations per run on a mixed selection; Clear resets it; whole-block Convert to block carries it to `textCase`/`fakeSmallCaps` (only when set, so other conversions are unchanged) and a partial convert puts it on the span. Under a style the span still stores the style's case in `data-textcase`, so Detach (`buildPropertiesFromState(state)`) writes it inline instead of dropping it. Both attributes are in `PARAGRAPH_STYLE_OWNED_ATTRS` and the three properties in `PARAGRAPH_STYLE_OWNED_PROPS`, so a span case counts as a conflict and is stripped when a style is applied. **QFT "Case (for selected text)" (v2.3.5+, #309):** writes the same span form through the font-style paths (caret `updateSpanPropertyInPlace(…, extraAttributes)`, `splitSpanAndApply`, Range `applyOrMergeStyling`, string fallback) with `buildInlineCaseApply()`, which always sends `data-fakesmallcaps` (`'true'` when allowed) because the writers merge over a span's old values; `normalizeInlineCaseSpans(html, start, end)` then rebuilds each touched span's case from its data attributes (drops a stale `font-synthesis-small-caps`, the `'true'`), leaves a span already in form byte for byte, and skips a `data-style-id` span that declares no case. Reset is `removePropertyFromSelection(…, 'data-textcase', …)`; `removePropertyFromSpan()` removes the whole case group for that marker. `parseInlineStylesAtCursor()` reports `textCase`/`fakeSmallCaps` (first span out with `data-textcase`), and `resolveSelectionStyleState()` captures them (own case when the span renders it, else the style's), so a style saved from selected text stores its case, the badge compares it, and `selectionHasOneStyleSet()` no longer treats a span case as a second set. The top-level QFT `textCase` stays the block attribute (the Inspector panel reads it); the selection's is in `selection`.
- **Format attributes must be registered:** `registerFormatType('typost/features', { attributes })` lists every `data-*` the inline editor writes. RichText's `create()` puts unregistered attributes in `format.unregisteredAttributes`, which `getActiveFormat().attributes` does not show and an `applyFormat()` rebuild drops. `data-fontstyle` was missing (since the Font Style control, 2.3.0): after a reload the Font Style select showed Inherit for italic text and one feature toggle rewrote the span without its italic (reproduced on mnc4, fixed with #214). Register any new span attribute there.
- Fit-to-width measurement applies the case declarations to the measuring node and re-measures on change, because capitals and small caps change widths. The QFT and inline feature previews (`caseStyleObject()`) also render the case, because `smcp`/`c2sc`/`case` look different on capitals.
- Accessibility: `text-transform` changes the text exposed to the accessibility tree; `font-variant-caps` does not. In the block the case is only on the `aria-hidden` visual copy, so screen readers read the stored text; an inline span has no hidden copy, so the inline All Caps help text warns that some screen readers spell out short all-caps words. Case mapping follows `lang` natively (Turkish `i` → `İ`), nothing in the plugin does case conversion.
- **kses:** see "Post content and kses" in [kses.md](kses.md) — `font-variant-caps` and `font-synthesis-small-caps` are on the plugin's `safe_style_css` list (#277).
