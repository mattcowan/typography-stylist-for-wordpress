# Post content and kses

- **Topic:** which CSS properties kses removes from content saved by a user without `unfiltered_html`, the plugin's `safe_style_css` list, the WordPress 7.0.1 limit for features and axes, and how to test a property against kses.
- **Issues:** #277
- **Code:** `typography-stylist.php` (`Typost::SAFE_CSS_PROPERTIES`, `Typost::allow_typography_css_properties()`), `tests/Unit/SafeStyleCssTest.php`

Moved from the "Important Notes" list of the root [CLAUDE.md](../../CLAUDE.md) by #361.

- **Post content and kses (v2.3.3+, #277):** a post saved by a user without `unfiltered_html` (Authors, Contributors; everyone but super admins on multisite) goes through `wp_filter_post_kses()`, and `safecss_filter_attr()` drops every style declaration whose property is not on the `safe_style_css` list. That covers inline spans and the Typography Stylist block's markup and its `content` attribute. `Typost::allow_typography_css_properties()` adds `Typost::SAFE_CSS_PROPERTIES` (`font-feature-settings`, `font-variation-settings`, `font-variant-caps`, `font-synthesis-small-caps`); every other property the editors write is already allowed, including `vertical-align`, `font-size` with `clamp()`/`min()`/`calc()`/`cqi`, and the `--typost-*` custom properties. Before #277 those users lost features, axes and small caps on save, and a Typography Stylist block with any of them became invalid (verified on the test site: real `wp_filter_post_kses()` over a saved post, block `isValid` false without the filter, true with it). **A new CSS property written into content must be checked against kses** and added to the list when kses drops it. kses still checks values: it rejects `\ ( & } =` and comments outside known CSS functions. **Limit — WordPress 7.0.1+ only for features and axes:** `wp_kses_attr_check()` decodes the attribute (`WP_HTML_Decoder::decode_attribute()`) before `safecss_filter_attr()` only from 7.0.1 (grepped across local installs: 6.8.5, 6.9–6.9.9 and 7.0 pass the raw value; 7.0.1+ decode; not backported to 6.9). The serializer writes `"liga" 1` as `&quot;liga&quot; 1`, so on older versions `explode(';')` cuts the value inside `&quot;` and the pieces fail the `&` check, with or without the filter (WP 7.0 + filter: `font-feature-settings: &quot;liga&quot; 1` → `1`). No hook runs before that split (`safecss_filter_attr_allow_css` sees only the pieces), so before 7.0.1 the filter keeps only small caps. **How to test:** run serialized markup (with `&quot;`) through `wp_kses_post()` or `wp_filter_post_kses()` — the path a saved post takes, correct on every version. A direct `safecss_filter_attr()` call models only one path: with decoded CSS (`"`) it matches 7.0.1+, and with `&quot;` it matches the raw-value behavior before 7.0.1 (on 7.0.1+ it would wrongly report an allowed property as dropped). Testing older versions only with decoded CSS hides their limit — that is how #277 first missed it. The fixes that would work there (single quotes in `save()`, or a placeholder round trip around kses) change saved markup or are fragile; not done.
