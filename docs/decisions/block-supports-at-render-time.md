# Block supports at render time

- **Topic:** why the block's color, spacing, alignment, anchor, class and Line indent reach the frontend through a `render_block` filter instead of `save()`, and how the Line indent interacts with the First Letter Hang and fit to width.
- **Issues:** #348 (v2.4.0), #364
- **Code:** `typography-stylist.php` (`Typost::add_block_support_attributes()`), `blocks/typography-stylist/block.json`, `blocks/typography-stylist/save.js`, `blocks/typography-stylist/style.css`, `blocks/typography-stylist/editor.css`, `tests/Unit/BlockSupportsRenderTest.php`, `blocks/typography-stylist/__tests__/text-indent.test.js`

## Block supports reach the frontend at render time (v2.4.0+)

`save.js` writes a bare `<div class="wp-block-typost">` and never calls `useBlockProps.save()`, and core's `getSaveElement` skips `blocks.getSaveContent.extraProps` for an apiVersion above 1 (`wp-includes/js/dist/blocks.js:3620`, WP 7.1.3). So the block's color, background, margin, padding, line height, alignment, anchor and class never reached saved markup, in any version. Changing `save()` needs a deprecation for every block with a setting, so `Typost::add_block_support_attributes()` (`render_block`) adds them instead: it sets `WP_Block_Supports::$block_to_render`, calls `apply_block_supports()`, restores the value, and writes the result on the wrapper; `add_text_indent_property()` then repeats core's `text-indent` as `--typost-text-indent` (#364), and the editor does the same with `withBlockTextIndentProperty()` (utils.js). Do not change `save()` to fix a block support: the attribute is stored either way, so a support in `block.json` reaches the frontend through this filter. The API is public and unchanged since WP 5.8 (read at the 5.8 tag); `block-supports/anchor.php` starts at 7.0, so the filter also reads `attrs.anchor`. Core's generated `wp-block-typost-block` is dropped so a block with nothing set stays byte for byte. Verified on mnc4 in Chromium: see `tests/Unit/BlockSupportsRenderTest.php` for the shapes.

**Line indent on the block (v2.4.0+, #348):** `block.json` declares `supports.typography.textIndent` (core's Text indent, sidebar label "Line indent"; WP 7.0+). Core writes it on the wrapper as an inline `text-indent` — `useBlockProps()` in the editor, the filter above on the frontend (`text-indent:24px;`, checked with core's real `wp_apply_typography_support()` + `apply_block_supports()` on 7.0 and 7.1.3; 6.9.4 ignores the unknown key and writes nothing). `save()` never reads `style`, so saved markup is unchanged (`__tests__/text-indent.test.js`) and the frozen v1/v2 deprecation `supports` stay as they are. **CSS (`style.css`):** `.wp-block-typost[style*="text-indent:"] > :is(.typost-styled, .typost-block-content):not(.typost-fit, .typost-fit-editing) { text-indent: var(--typost-text-indent) !important; --typost-hang-on: 0 }`. The wrapper repeats its Line indent as `--typost-text-indent` (#364: the filter above on the frontend, `withBlockTextIndentProperty()` in the editor), so the visual copy reads the value itself and an em indent resolves against the text's size, not the wrapper's; without the property, `var()` is invalid at computed-value time and the copy inherits the wrapper's value, as before. The rule reaches the visual copy past a theme's heading/paragraph indent; `!important` because a paragraph style's indent rule on S is (0,7,0)+ and the editor hang rule (`.typost-hang`, editor.css) has the same (0,4,0) specificity in another file — so the block's own setting beats the style, as on a core Paragraph (and the hang's negative `text-indent` in the editor is replaced). `--typost-hang-on: 0` turns the First Letter Hang off, as a style's first line indent does (#199): the frontend `::first-letter` margin goes to 0 and the editor shows the inherited indent, so both show the indent alone; mixing them could not match (the editor hang is `text-indent` on the same element, and the wrapper's value cannot enter a `calc()` there). The hidden screen-reader copy inherits the indent too — it is absolutely positioned, clipped and nowrap, so nothing shows; the Narrator focus outline follows the box, not the text. **Fit to width ignores it:** `.wp-block-typost .typost-fit, .wp-block-typost .typost-fit .typost-line { text-indent: 0 }`, because each frontend line is `display: block` and would be indented and pushed past the measured width (in the editor the lines are inline, so only line 1 would move: an editor/frontend mismatch). This also stops a theme's `p + p { text-indent }` from indenting every fit line — a fix, but fit blocks under such a theme render differently after the update. Measurement did need a change: `measureFitLines()` (`hooks/use-fit-measurement.js`) measures a hidden copy of the heading that keeps `typost-fit-editing`, drops `typost-fit` and resets `text-indent: 0` inline without `!important`, so the rule matched the copy and measured it wider by the indent (a 1em block measured 0.0704 instead of 0.0757); the `.typost-fit-editing` exclusion fixes that (#364). `initialHangApplies()` needed no change. Detach on a fit block writes no Text indent (`buildDetachBlockSettings()` skips the first line indent for fit, as the style never applied it). `hasBlockTextIndent(style)` (utils.js; a truthy value, matching the CSS's presence test — core's style engine writes the string `'0'` but nothing for a number 0 or `''`: PHP `is_valid_style_value()`, JS `generateRule()`, checked on 7.1.3) drives two Inspector notes: "The hang has no effect while the block has a Line indent…" (First Letter Hang panel, non-fit, only with a hang above 0) and "Fit to width does not use the Line indent setting…" (Font Size panel, fit). Detach from a style keeps the style's first line indent here on WP 7.0+: see `paragraph-styles/CLAUDE.md`, "Detach keeps a first line indent in core's Text indent (#348)". The theme setting `typography.textIndent: false` hides the control; a value already stored still renders (core's PHP output checks only the block support).
