# First Letter Hang

- **Topic:** how the first letter hangs past the start edge (`initialHang`, `fitLineHangs`) on the frontend, in the editor and on fit-to-width lines, and how the plain typography switch (`.typost-plain`) turns it off.
- **Issues:** #242, #315
- **Code:** `blocks/typography-stylist/save.js`, `blocks/typography-stylist/style.css`, `blocks/typography-stylist/editor.css`, `assets/css/frontend.css`, `blocks/typography-stylist/utils.js`, `blocks/typography-stylist/hooks/use-fit-measurement.js`, `typography-stylist.php` (`Typost::add_fit_line_plain_properties()`), `paragraph-styles/paragraph-styles.php`, `paragraph-styles/assets/js/lib/ps-utils.js`

**First Letter Hang (v2.3.2+, #242):**
- Block attributes `initialHang` (number, em, default 0) and `fitLineHangs` (array, default `[]`). Moves the first letter past the start edge so a swash capital (Bookmania's `swsh` caps were the motivating case) hangs into the margin while the letter's main shape aligns with the text edge. Typography Stylist block only: the inline format could only do it by wrapping the letter in a span, which splits the word for screen readers; `::first-letter` adds no element. On core Paragraph/Heading blocks with a style (#219) the hang comes from per-style rules the paragraph-style generators add for a style with a hang (`::first-letter` frontend, `text-indent` in the editor, `has-text-align-*` guards), because this file's rules are scoped to `.wp-block-typost` and are not loaded on core-block-only pages.
- **Values are custom properties, consumed by one shared rule set in `style.css`.** An inline style cannot reach a pseudo-element, so `save.js` writes `--typost-hang: N` (only when > 0 and no `styleClass` — byte-identical output for existing blocks) and the paragraph-style generators write `--typost-hang: N` into the style's main rule (`initialHang` is a style-owned property: captured, diffed, normalized to 0 on apply, sanitized, emitted by both CSS twins). Frontend, non-fit: `.wp-block-typost > .typost-styled:not(.typost-block-content, .typost-fit)::first-letter { margin-inline-start: calc(var(--typost-hang, 0) * var(--typost-hang-on, 1) * -1em) }`. Note this sets a 0 first-letter margin on every visible copy; it overrides only a theme's own `::first-letter` margin on this block, which was judged negligible.
- **Fit-to-width uses no `::first-letter` (Firefox).** Firefox does not carry a block's `::first-letter` into a block-level child, and frontend lines are `display: block`, so line 1 got no hang there while measurement still sized it as hung and it ran past the right edge (PR review; reproduced 2026-10-07: Chromium 145 −36px, Firefox 146 0px). Every fit line hangs through a start margin on its own wrapper, in the editor and on the frontend, from `style.css`: line 1 via `.typost-fit > .typost-line:first-child` reading the inherited `--typost-hang` (from `initialHang`, so a style drives it — save wraps every line, and the editing value leaves an empty line 1 unwrapped so its `<br>` is the first child); lines 2+ through `--typost-line-hang:N` on their own `span.typost-line` (`buildFitLineOpenTag()` in utils.js, shared by `buildFitLinesHtml` and `wrapFitLines`, never writes index 0), consumed as a start margin. `measureFitLines()` (`hooks/use-fit-measurement.js`) subtracts `hang × 100px` per line (`computeHungFitRatio`, `resolveFitLineHang`) so each line's ink still ends at the right edge; re-measures on `initialHang`/`fitLineHangs`/`textAlign`. `fitLineHangs` is content (like `fitLineSizes`): never in the apply bridge, never in styles; its entries stay put when lines are inserted above them.
- **Alignment guard:** `--typost-hang-on: 0` for centered text and end-aligned text (`:dir(ltr)` right / `:dir(rtl)` left — separate rules so a browser without `:dir()` drops only those), matched on the inline `text-align` (both `text-align:center` saved and `text-align: center` React forms). `initialHangApplies()` is the JS mirror the measurement uses.
- **Editor uses no `::first-letter` (caret bug).** Verified 2026-10-07 in Chromium: with `::first-letter` on the contenteditable, Home lands *after* the first letter (typing produced "TXhe") and Shift+Home leaves it unselected; clicking was fine. Core's drop cap avoids the same bug with `:not(:focus)`. The editor renders the non-fit hang with `text-indent` (first line only, em = block size) in `editor.css`, gated on the editor-only class `typost-hang` (set by edit.js when `normalizeHang(initialHang) > 0`) so a theme's `p { text-indent }` on other blocks is untouched. Known divergence: text-indent's em is the block's size, `::first-letter`'s is the letter's, so they differ only when an inline font size wraps the first letter.
- **Plain typography switch (v2.3.5+, #315):** documented in HOOKS.md. `.typost-plain` on any ancestor (frontend.css) sets `--typost-plain: 1` and resets `font-feature-settings: normal !important` on `.typost-styled` and descendants, except editor content (`.editor-styles-wrapper`, `.block-editor-block-list__block`: a page can mount the editor on the frontend, not in an iframe, and the feature reset is not a custom property that the editor can turn back off — PR #325 review); the bare property removes hangs only (a custom property cannot switch a string property). Every frontend hang margin multiplies by `(1 - var(--typost-plain, 0))` — style.css's three rules and the paragraph-style `::first-letter` rule (PHP + JS twins; the editor `text-indent` rule is not gated). Fit lines: a hung line with its hang removed is hang × size too wide, and fits at size ÷ (1 + R × hang). R and the size are literals in the inline font-size, so `Typost::add_fit_line_plain_properties()` (`render_block`, regex, no WP_HTML_Tag_Processor because WP 5.8 is supported) copies them into `--typost-fit-ratio` / `--typost-fit-size` at render time, and style.css divides with `!important` (divisor uses `--typost-hang-on`, so lines measured unhung keep their size). Save output is unchanged (no deprecation) and old content is covered. Frontend only: `.wp-block-typost.block-editor-block-list__block` resets the property, and editor lines never get the render-time properties. The paragraph-style CSS transient key was renamed to `typost_paragraph_styles_css_v2` so updates do not serve the ungated CSS for 12 hours. Verified on mnc4 (Chromium + Firefox, simulated 0.2/0.1 em hung lines on draft 16639): off −16.8/−7.2px start, on 0/0 start, end overflow ≤ 0.3px; switch-off sizes equal the inline sizes; runtime toggle restores the layout. Not re-measured: a feature reset that changes glyph widths can shift fit lines a little.
- `normalizeHang()` exists three times (core utils.js, ps-utils.js, PHP `Typost_Paragraph_Styles::normalize_hang()`): PHP `is_numeric()` semantics (JS rejects `'0x1A'`/booleans), cap `INITIAL_HANG_MAX`/`HANG_MAX` = 1, three-decimal rounding by textual exponent shift to match PHP `round()` on half-steps, values < 0.0005 → 0 (also dodges `String(1e-7)` exponent form). Keep them identical.
